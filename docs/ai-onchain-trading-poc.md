# Monad 链上模型自动交易 PoC

目标：证明神经网络可以在 Monad 合约内计算买入、卖出、持有决策，并驱动 DEX 兑换。收益率不作为成功条件。

当前状态：已拆解原模型、完成合成输入的 PyTorch/整数对照与本地 EVM 推理原型。尚未完成真实 MON 输入适配、兑换集成或公共链部署。详细结果见 pretrained-model-onchain-study.md。

## 模型适配边界

Neurom 的 DensePolicyEngine 使用整数权重、位输入以及 FF 阈值或 LIF 激活。
上游使用 Stable-Baselines3 的 MlpPolicy。不能把权重文件直接放进 Neurom。

优先保留原模型 actor 并实现 int16/Tanh 定点推理，研究原型见 pretrained-model-onchain-study.md。

Neurom 蒸馏作为备选路线（尚未实施，不能把蒸馏结果称为原始预训练模型）：

1. 使用已下载的 Adilbai/stock-trading-rl-agent PPO 检查点，见 research/ai/README.md。
2. 固定原模型的输入、输出和标准化协议，建立 MON/USDC 数据适配器。
3. 记录教师的确定性决策，训练兼容 Neurom 的整数学生网络。
4. 在单独保留的数据上报告教师与学生的动作一致率及混淆矩阵。
5. 对同一个整数学生模型，逐项比较 Python、JS 和 Solidity 的输出。
6. 部署学生权重和引擎，并把模型合约接入交易执行器。

这条路线证明的是“由交易模型蒸馏得到的整数策略能上链”。
它不证明原始 PPO 浮点模型已被逐参数、逐算子等价部署。
如果要求原始 PPO 上链，需要另做定点激活引擎并报告数值与决策误差。

## 工程创新点

以下是本项目可验证的组合设计，不主张未经检索的学术或专利新颖性。

### 1. 推理与兑换在同一笔交易内完成

交易执行器调用 Neurom 模型，再按模型输出选择 MON 到 USDC、USDC 到 MON，或持有。
触发者提交数据引用和执行约束，不提交最终买卖方向。
模型推理、限制检查、兑换及余额结算全部成功，交易才提交。

验收：买入、卖出、持有都有可核对的执行记录。兑换失败时状态全部回滚。
合约不得接受任意 router、任意 calldata 或任意收款地址。
执行器自行构造目标池的调用，并检查实际余额变化。

### 2. 每笔 AI 决策都有可重放记录

记录模型产物哈希、特征协议版本、输入哈希、市场观察窗口、会话、决策编号、
动作、分数摘要、交易前后余额和执行状态。
保留完整输入及输出，允许独立脚本从同一份权重重算结果。

验收：固定权重和输入时，链上与本地整数推理结果完全一致。
教师与学生的一致率另行报告，不能混成一个“100% 一致”指标。
哈希证明记录未变，不单独证明行情真实。

### 3. 使用链上市场观察构造模型输入

逐步把关键特征从服务器提交改为合约从固定池状态和持仓读取。
用按时间或区块间隔采样的价格记录构造短周期回报。
特征的缩放、裁剪、位编码和缺失规则全部版本化。

第一版可使用授权数据提交者，明确记录这个信任假设。
后续可加入链上采样和时间窗口，减少提交者任意选择输入的能力。
单次池内现价仍可能受操纵，不能称为无需信任的预言机。

验收：错误池、过期窗口、重复决策编号和非法输入都不能产生兑换。

### 4. 模型可替换，执行约束保持独立

模型只输出动作。执行器独立限制交易额度、持仓、最小输出、冷却时间和允许交易的池。
记录模型版本切换，并允许暂停。

验收：即使模型连续输出买入，也不能突破执行器限制。
换模型后，前端仍能显示统一的决策与交易记录。

## 当前确认的产品范围

第一版只使用已有的 Uniswap V4 MON/USDC 池，不做跨池选择。
池 ID 为 0x18a9fc874581f3ba12b7898f80a683c66fd5877fd74b26a85ba9a3a79c549954。
作者发布、用户选择策略和作者收费属于后续策略市场。
策略市场中的策略合约本身也部署在 Monad，网页和 keeper 不代替策略合约计算决策。

真实数据快照见 research/ai/mon-usdc-demo-data.json。
数据库中有 1,574 个 Monad 池目录条目，其中 108 个记录正流动性。
目录覆盖不能当作已经实现多池交易。当前双向交易代码固定为本池。

第一版分开显示三个阶段：

1. 决策预览：显示模型输入、买入/卖出/持有与原始动作值，明确运行位置。
2. 链上决策：在 Monad 策略合约内计算动作，保存输入和模型版本以供重放。
3. 兑换执行：同一笔交易按链上动作执行固定池兑换，并验证余额变化。

只有完成第二阶段后，页面才能标为“链上 AI 决策”。
没有可用输入时，状态为“数据不足”，不能把输入错误显示成模型 HOLD。
没有可用余额时，保留模型原始动作并单独显示“无法执行”，不能伪称模型选择持有。
HOLD 不调用 DEX，也不收成交费。交易失败不收策略作者的成交费，gas 仍按链规则发生。

## 第一版范围

- 交易对：现有 MON/USDC Uniswap V4 池。
- 动作：HOLD、BUY_MON、SELL_MON，固定编号。
- 模型：先加载现有 PPO 权重并核对输入输出。保留原始模型与采用 Neurom 蒸馏网络是不同路线，当前未声称完成任一路线。
- 执行：合约持有策略资产，外部 keeper 定时触发。合约不会自行定时运行。
- 展示：在现有前端加入策略状态、模型哈希、最近动作、输入、交易哈希与本地核对结果。
- 先在本地链验证，再在 Monad 公共测试网验证。真实 DEX 执行可使用主网 fork；
  fork 记录与公共链交易记录必须分别标注。

## 验收指标

| 指标 | 验收方式 |
| --- | --- |
| 整数模型推理一致性 | 保留样本与边界样本的分数、动作、状态逐项相等 |
| 教师与学生一致性 | 单独报告准确率、各动作召回率与混淆矩阵 |
| 买入、卖出、持有 | 三类动作均通过集成测试 |
| DEX 执行真实性 | 实际 router 调用、余额变化与交易收据 |
| 原子性 | 兑换失败不推进会话、决策编号或资金状态 |
| 输入与会话约束 | 拒绝过期输入、重放和跨会话污染 |
| 部署与执行成本 | 以实测部署 gas、推理 gas 和兑换 gas 报告，不预填数字 |
| 收益 | 仅作为观察数据，不作盈利承诺或成功门槛 |

## 实现顺序

1. 已有模型的加载、数据与动作适配，以及 actor 导出。
2. 本地整数推理与 Neurom 合约的一致性验证。
3. 交易执行器及现有 V4 路由的合约侧集成。
4. keeper、前端记录和完整流程演示。
