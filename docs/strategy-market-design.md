# 策略市场：当前状态与接入方案

## 当前已经实现

`选池/contracts/src/MonUsdcRouteSelector.sol` 是固定白名单内的 14 池报价择优合约。旧 `MonUsdcQuoteSelector.sol` 六池版本保留为历史基线。
`选池/contracts/src/DcarV2Router.sol` 是有限候选的 V2 整数拆单算法合约。
网页切换这两个内置策略。用户可以用钱包部署副本。部署地址只保存在当前浏览器，不是链上市场登记。
网页使用的两个策略合约不管理资金，没有作者所有权、调用收费、交易执行或收益分账。只读 `eth_call` 不会向作者支付费用。

## 与本地 neurom 项目的区别

本项目直接部署 Solidity 算法合约，并比较浏览器与链上的结果，没有调用 neurom 的 ModuleFactory、NeuromModule 或神经网络引擎。
本地 neurom 的 `docs/adr/0014-deployment-is-per-artifact.md` 与 `contracts/src/modules/ModuleFactory.sol` 描述工厂方案：每份产物对应模块，模块关联固定引擎版本与权重块，工厂记录模块身份。模块持有 owner 身份，外部付费应用负责向 owner 支付费用。
算法策略不需要虚构神经网络权重。可以采用独立的策略工厂和统一接口，之后用适配器接入 neurom 模块。

## 市场需要新增的组件

1. `IStrategy`：统一输入输出封装，并声明策略类型和接口版本。V2 储备分配与 V4 报价择优必须区分输入语义。
2. `StrategyRegistry`：记录策略地址、代码版本、作者收款地址、费用及启用状态。注册不代表策略安全或报价可信。官方策略和第三方策略应有清楚标签。
3. `StrategyExecutor`：读取用户选择的策略，使用只读调用取得决策，再校验可用池、资产、输入上限、滑点和截止时间。执行成功后在同笔交易中结算作者费用。失败整笔回滚。
4. 前端市场：浏览策略、选择版本、显示作者和全部费用、连接钱包签名、展示决策与执行记录。第三方策略不获得用户无限授权。

第一版可以登记现有算法策略，不需要先训练模型。登记、收费与兑换均属于待实现范围。用户当前输入的 0.1 MON 只是报价数量，不代表策略调用费或部署费。

## 部署路径

可先使用注册表登记独立策略合约，方便验证市场交互。策略实例增加后，再使用工厂部署带固定配置的实例，减少重复部署代码。
如果要支持 neurom 的训练产物，需要单独部署或连接其官方工厂、引擎和模块，再实现遵守 `IStrategy` 的适配器。当前尚未完成该接入。
