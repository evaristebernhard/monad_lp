# 独立单文件最优报价购买

给另一台电脑的运行文件是 [`buy-standalone.mjs`](../examples/monad-best-buy/buy-standalone.mjs)，配置模板是 [`standalone.env.example`](../examples/monad-best-buy/standalone.env.example)。脚本已内嵌候选池目录、路由编解码和签名依赖；运行时只依赖 Node.js 和网络，不需要项目目录、`npm install`、`node_modules`、`catalog.json`、`bestSwap.mjs`、本地数据库或本地 Rust 后端。

## 1. 在另一台电脑准备文件

安装 Node.js，本次验证版本为 **24.18.0**。把上述两个文件放在同一文件夹，将 `standalone.env.example` 复制或重命名成 `.env`。Windows 注意不要保存为 `.env.txt`。

`.env` 配置：

```dotenv
MONAD_API_URL=https://api.chayu123.me
MONAD_RPC_URL=https://rpc.monad.xyz
PRIVATE_KEY=你的本机签名私钥
```

`MONAD_API_URL` 是报价服务的域名，不要在后面加 `/api`；备用入口为 `https://lp.chayu123.me`。`MONAD_RPC_URL` 必须连接 Monad 主网 143，并支持读取、模拟及发送交易；可以换成你自己的 RPC。网站的 `/api/monad/trade-rpc` 是只读代理，不能用来广播。

私钥只在签名电脑配置。服务端只收到报价请求；脚本在本机签名，然后通过你配置的 RPC 广播。钱包需要持有足够的 MON 支付兑换本金和 gas；这里只购买原生 USDC。

## 2. 先预览，再真实购买

在这两个文件所在文件夹打开终端。

```bash
# 只获取报价：不需要私钥，也不需要额外 RPC 核验
node --use-env-proxy --env-file=.env buy-standalone.mjs 0.1 --quote-only

# 交易预览：配置私钥后会自动取该钱包地址，不广播
node --use-env-proxy --env-file=.env buy-standalone.mjs 0.1

# 真实使用 0.1 MON 购买 USDC，另付 gas；每次执行是一笔新交易
node --use-env-proxy --env-file=.env buy-standalone.mjs 0.1 --send --record buy-001.json
```

未配置私钥时，可以用 `--wallet 0x你的地址` 预览；`--send` 必须配置私钥。

`--use-env-proxy` 让 Node 使用 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 环境变量。没有这些变量时正常直连。若浏览器或 curl 走了代理，而 Node 没有相同设置，就可能出现“浏览器能打开但脚本 fetch failed”；需要把有效代理地址配置到终端环境。Node 不会凭浏览器设置自动知道代理地址。该参数已在 Node 24.18.0 实测，较旧 Node 版本不识别时请升级。

## 3. 一次执行做什么

1. 请求后端最优报价，按整数检查所有候选及后端选中的最高输出。
2. 用你配置的 RPC 核对主网链 ID、区块哈希、候选池身份和同区块精确输出。
3. 按实际获选协议构造交易，不退回固定池。当前支持 Uniswap V2/V3/V4 和 PancakeSwap V3 的已核验候选。
4. 设置最低到账和截止时间。默认滑点 50 bps，即 0.5%；gas 另计。
5. 只有加 `--send` 才估算 gas、检查余额、本地签名并广播；随后查询回执，核验钱包实际收到的 USDC。

默认比较全部 14 个已接入的 MON/WMON–USDC 直接池，不代表全链所有池的最优路线，也不扣 gas 排序。脚本目前仅执行 **MON → USDC**；反向兑换不在此单文件的执行范围中。报价服务和你选的 RPC 仍需在线。

可选参数：`--slippage-bps 50`（范围 1–100）、`--min-usdc 0.002`、`--record 文件名.json`。`--protocol` 会把选择范围限制到指定协议，不再表示全部候选的最优结果。`--help` 查看命令说明。

## 4. 如果发送或确认超时

签名后、广播前，脚本先将交易哈希写入记录文件，再打印 `transaction_hash=...`。记录仍为 `submitted` 时，同一记录文件会阻止再次发送。

遇到超时，先查记录中的交易哈希，确认是否已上链；不要删记录、换记录文件或反复执行 `--send`。`confirmed` 表示脚本已确认成功，`reverted` 表示回滚。一次新购买应使用新的记录文件名。
