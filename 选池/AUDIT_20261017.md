# DCAR 选池算法审计与首版实跑

日期：2026-10-17。此次只审计和运行选池算法，未新增网页指标。
这是一套确定性交易路由算法，不需要训练模型，与股票 PPO 独立。

## 裁决

- 独立、同交易对、固定状态的 V2 精确输入路由：算法思路可保留。
- 目录中任意 1,000～2,000 个池混在一起直接求解：不成立。必须先按代币、方向、协议和可执行性筛选。
- 直接把现有 Uniswap V4 MON/USDC 池代入 V2 储备公式：不成立。
- 原 Python 实现进入执行环节前存在输入和证书可行性缺口，本轮已修复具体复现问题。
- 本轮已部署测试网的，是基于真实 V4 Quoter 快照的 K=1 单池择优基线，不是完整 DCAR 拆单。

## 2. 按优先级排列的发现

### 高：证书没有证明旧路线可行，而且把冲突下界钳制成“上界”

原 IncrementalDualCertificate.recheck 和 certificate_after_updates 只检查每条分配是否超出单池容量。
它们没有验证池子去重、投入总量守恒、最多 K 条、正数金额或未知池。
随后使用 max(lower, upper) 遮盖矛盾，有机会把无效路线写成零 Gap。

具体复现：只有一个储备 1,000/1,000、零费率的 V2 池，输入 100。
可行最优输出为 90.9090909。
把同一池伪装成三条各 100/3 的独立分配后，原实现按三次独立储备计算 96.7741935，
再把 upper 提到同一数值，返回 certified_can_reuse=true、gap=0。
这不是对偶公式本身失效，而是传入的下界根本不是可行解。

修复：统一验证路线去重、金额守恒、K、池身份、金额和容量。
显著的 lower>upper 现在报证书无效，不再默默钳制。
增量索引在构造与更新时验证池数据，复查仅访问当前路线的 K 个池，保留增量复杂度。

### 高：零容量在 CLI 中被当成无限容量

原 scalable CLI 使用 if p.get('cap_in')，把 0 转成 None。
这绕过了 Pool.validate 对零容量的拒绝。
修复为显式区分 None 和数值 0。零容量配置会报错，不会成为可交易池。

### 中：非有限数值进入求解过程

原 reserves 和 gas 校验允许 NaN 或正无穷，amount/aversion/base_gas 也没有统一有限性检查。
后续数学运算可能出现 NaN、错误排名或不可用证书。
修复：池和问题参数先做有限性检查、正数/非负约束及风险权重检查，再求解。
更新批次整体验证后才写入索引，避免一批更新只改到一半。

### 中：shortlist 小于 K 时误报全局不可行

原候选集可能只有一个池，但全池集合需要三个容量受限池才能满足输入。
示例为三个 cap=40 的池，Q=100，K=3，shortlist=1。
全局可行，原实现却报 No feasible set。
修复：候选集至少保留 min(K,N) 个池，并先保留容量覆盖组合。

### 中：绝对金额阈值会丢掉小额分配

原 optimize 忽略 x<=1e-8 的分配，导致小额输入可能被当成零路由。
修复：保留所有正分配，并用随输入规模变化的守恒容差。
这仍是浮点研究求解器，不是原始代币整数精度的链上结算器。

### 高优先级工程限制：V2 证书不覆盖 V4

DCAR 的 q(x)=Ya*x/(X+a*x) 与边际反解依赖独立 V2 曲线。
V4 的跨 tick、当前费率、Hook 和实际报价不能通过总 TVL 或虚构储备替代。
原生 MON 与 WMON 也不能仅凭名字合并，中间包装需要独立执行路径。
本轮没有把真实 V4 池输入 V2 DCAR，而是增加独立的只读 V4 Quoter 基线。

### 尚未消除的边界

- 对偶上界是给定数学模型的结论；当前浮点计算不是区间算术证明或链上证明。
- shortlist 内枚举不等于全局枚举。Gap 较大必须扩大候选集或重算，不能总称全局最优。
- 固定 gas 成本和 risk_weight 都是外部输入假设，不是实际结算成本或统计置信度。
- 所有变化池必须进入增量更新。漏报更新、跨块拼数据或共享底层池会破坏问题定义。
- 算法解决“给定交易怎样执行”，不决定投资者是否应该买入，也不是 LP 收益预测。
- 本轮没有进行原始文档中的“全球首创/获奖重复性”检索，不认可未经证实的创新性结论。

## 3. 修复后的算法实跑

新增 9 项回归测试通过。
原验证脚本再次通过：120 个有容量约束的小实例与完整枚举比较，上界没有被参考最优值突破。
这批问题最差报告 Gap 为 3.57787%，证明它并非始终精确。

12 次/规模合成压力测试的结果见 results/verification.json。
当前机器的求解中位数约 0.16 秒（1,000 池）和 0.20 秒（2,000 池）。
这些是 CPU-only 合成数据，不是 RPC 时延、真实主网成交或相对成熟聚合器的提升。
对选中池人工降低 2% 输出储备，旧路线的 Gap 升至约 1.8887%，复用被正确拒绝。

## 5. 第一版测试网算法

合约：contracts/src/MonUsdcQuoteSelector.sol。
职责：在固定的 6 个主网候选池报价中，用整数比较选出最大输出。
并列时选择较小的 Pool ID，防止报价输入顺序改变结果。
要求候选集完整、无重复、池 ID 已注册，输入方向只允许 MON/USDC。
返回所选池、输出和重放哈希。

测试网部署地址：
https://testnet.monadscan.com/address/0x36a71946f5c9a6627dd7fcd464a6f5abc604f4ca

部署交易：
https://testnet.monadscan.com/tx/0x4a520f2c90b5a4182a78393f036c0ba75f83373fcfb32c3362356ba9847d7188

链 ID：10143。
8 项本地合约测试通过，6 组快照在测试网 eth_call 中重放，所选池、输出、重放哈希均与本地一致。
部署收据、runtime hash 和全部重放结果：results/testnet-deployment.json。

必须区分：

- 该合约的择优运算真实发生在 Monad 测试网。
- 输入是主网报价快照，不是测试网流动性。
- 报价由调用者提供，合约没有验证报价来源或时效，不应接资金。
- 不持有资产、不授权、不调用 DEX，没有发生兑换。
- 它是 K=1 V4 报价择优基线，不是 DCAR 多池分配器或全链全局最优证明。
- 6 次重放是只读调用，没有把每次决策写成链上交易历史。

这份首版用于证明链上确定性选池和重放能力。接资金前，必须让合约自行调用可信 Quoter，
或采用明确授权的数据验证机制，并集成 minOut、截止时间、资金边界及完整原子模拟。

## 6. 配置与签名边界

参考了 examples/monad-buy-usdc/.env.example，但忽略其中主网 RPC，只在进程内读取签名材料。
该示例文件含真实私钥值，不适合作为可公开分发的示例。未复制密钥到本目录、日志或结果。
新的 .env.example 使用空占位符，支持 TESTNET_DEPLOYER_PRIVATE_KEY 环境变量。

部署脚本在签名前核对 eth_chainId==10143，限制 gas、gas 价格和费用上限。
不读取主网余额、不签署主网交易。收到广播 hash 后立即记录，防止超时后重复部署。
有部署记录时再次执行 --deploy 会拒绝重复广播。
没有修改原示例的钱包配置，也没有轮换用户密钥。

## 7. 下一步顺序

1. 保留修复后的 DCAR，作为独立 V2 拆单求解器。
2. 保留 V4 精确报价 K=1 基线，先完成执行前验证，不急于新指标。
3. 如果扩展 V4 拆单，接分段报价/Quoter 分配优化，单独审计其整数与执行一致性。
4. 不能把 V4 启发式结果贴上 V2 对偶证书标签。
5. 作者收费与策略市场后续接入，不混进本轮算法正确性判断。
